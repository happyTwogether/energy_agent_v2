# 单小区节电报告状态与时延设计

日期：2026-08-20

状态：已确认，待实施

## 目标

修正单小区节电空间报告将“未查到扩展结果”误写为“没有可扩展时段”、将未知白名单状态误写为“未命中白名单”的问题；过程表只展示可完成低业务与休眠联合判断的时点。单小区节电报告由工具确定性生成，避免工具调用后的第二次大模型改写，并留下可定位的阶段耗时日志。

本次仅修改当前 AgentScope `app/` 运行链路和测试，不改数据库表结构、V1.4 扩展/收缩算法或 Durable A2A/MCP 运行时。

## 已选方案与取舍

采用“显式业务状态 + 工具直出报告”方案。

- 备选一：仅修改提示词文案。不能让模型区分空结果、无候选和过程缺失，仍会产生错误因果推断，弃用。
- 备选二：在工具中显式建模状态、但仍让模型二次总结。能修正结论，却保留不必要的第二次模型等待和改写风险，未选。
- 备选三（采用）：工具返回可复核的三态结果和固定 Markdown 报告；AgentScope 现有 `DirectAnswerMiddleware` 直接返回该报告。智能体仍负责理解问题、选择工具和数据分析，固定报告仅负责准确呈现已经得到的结论与依据。

## 扩展结果与过程证据

### 扩展结果状态

工具新增 `expansion_result_status`：

| 状态 | 判定 | 对外结论 |
|---|---|---|
| `unavailable` | 当日扩展结果表没有该 CGI 记录 | 当日未获得扩展分析结果，暂不能判断是否需要扩展。 |
| `no_candidate` | 有扩展结果记录，但两套候选时窗均无可扩展小时 | 已完成扩展评估，当前未识别需新增的扩展时段，保持现有配置。 |
| `candidate_available` | 至少一套候选时窗存在可扩展小时 | 已识别可扩展候选，展示两套候选和连续部署结果。 |

只有存在扩展结果记录时，候选表才展示小时数；不得把空记录默认成“0 小时”或“非高负荷”。

### 低业务与休眠情况分析表

小时级过程数据仍按 22、23、0 至 7 时取数，但展示前仅保留同时具备 `low_flow_pct` 和近 15 天平均休眠时长的时点。缺少任一数据的时点不在表中显示，也不能被写为“0 秒”“数据缺失导致无可扩展时段”或任何扩展结论。

工具新增 `expansion_process_evidence_status`：

- `complete`：10 个分析时点均具备联合判断数据；
- `partial`：只展示其中具备联合判断数据的时点；
- `missing`：没有可展示的联合判断时点。

过程证据仅用于复核，最终扩展结论始终以扩展结果记录的 `hour_filter` 等字段为准。

## 白名单状态

工具新增 `whitelist_status`，不再把缺少结果或缺少字段归为 false：

| 状态 | 对外文案 |
|---|---|
| `whitelisted` | 该小区命中节电白名单；展示已返回的原因和有效期，并提示修改前确认业务影响。 |
| `not_whitelisted` | 该小区不是节电白名单小区，当前无白名单限制。 |
| `unknown` | 未获得白名单状态，暂不能判断是否受白名单限制。 |

完整分析同时检查扩展和收缩来源：任一来源明确命中即为 `whitelisted`；两侧都未明确返回时为 `unknown`；只有至少一侧明确返回否且没有命中时才为 `not_whitelisted`。扩展/收缩的业务触发 `reason` 不得冒充白名单原因。

## 报告与性能

`analyze_single_cell_energy` 在结构化结果组装完成后生成 `report_content`。报告按已确认的扩展、收缩、白名单章节输出，直接使用候选、部署、收缩和参数核查表；空的收缩/休眠前证据以一句“未返回相应分析结果”代替空表。现有 `DirectAnswerMiddleware` 因此跳过第二轮模型调用。

工具记录并返回 `performance` 阶段耗时（毫秒）：最新日期查询、小区名称解析、扩展查询、收缩查询、休眠前负荷查询、参数核查、报告组装和总耗时。每个阶段记录结构化日志，供生产日志定位；这些内部时延不写入用户报告。

## 验收

1. 无扩展结果记录时，报告只说明暂不能判断，不输出“无可扩展时段”、`0 小时`、默认非高负荷或“数据缺失导致无可扩展时段”。
2. 有记录且候选为空时，明确说明已评估且当前无需新增扩展时段。
3. 过程表只出现低业务与休眠数据齐全的时点；缺失时点不出现。
4. 白名单明确为否时，输出“不是节电白名单小区”；缺少来源时输出未知；任一来源为是时保留白名单风险信息。
5. 单小区工具返回 `report_content`，真实 AgentScope 生命周期只调用一次模型。
6. 日志可定位各数据库/渲染阶段耗时，且所有现有单小区、批量分析、导出与中间件测试保持通过。
