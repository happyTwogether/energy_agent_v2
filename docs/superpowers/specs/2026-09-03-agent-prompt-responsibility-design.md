# 能效智能体提示词职责重构设计

## 背景

生产问题“查询5G小区460-00-2539193-71在2026年8月24日的深度休眠时长和深度休眠开关”错误调用了 `analyze_single_cell_energy`，最终生成完整节电分析报告。正确行为应是调用 `query_business_data` 查询用户明确要求的两个字段。

这不是缺少一条针对具体问法的规则，而是执行提示词、工具描述和遗留参数规则对“查指标”给出了互相重叠的指令：

- 执行提示词仍有“查指标时调用对应业务工具”的旧表述。
- 执行提示词仍描述已经撤下的“按中文名查询单小区指标”路由。
- `analyze_single_cell_energy` 的描述覆盖“节电详情”，但没有声明它不用于读取字段值。
- 现有测试只断言提示词包含若干文字，没有把真实用户目标映射为预期工具的可维护契约。

## 目标

- 让“读取数据”和“生成专业业务结论”成为互斥、稳定的一级路由。
- 不为单条用户问法增加特例，也不在主提示词维护字段清单。
- 不增加独立意图识别模型或额外 LLM 调用，保持现有响应链路和延迟。
- 让提示词、工具描述、JSON Schema、Python 业务代码和结果总结各自只承担一种职责。
- 保持现有节电报告的业务口径、格式和 Python 确定性计算不变。

## 非目标

- 不修改数据库查询规划器、授权目录或确定性指标公式。
- 不改变扩展、收缩、白名单、参数核查或异常诊断的业务阈值。
- 不将专业诊断工具合并进 `query_business_data`。
- 不引入 embedding、外部服务或新的 Python 依赖。
- 不依赖关键词硬编码的 Python 前置路由器。

## 总体架构

继续使用现有单次原生 function calling 架构。模型同时看到八个工具，由简短的执行提示词和互斥的工具描述共同完成选择；工具执行完成后，中间件根据工具名称选择对应总结提示词。返回 `report_content` 的工具继续由直出中间件原样返回，不再让总结模型重做确定性报告。

各层职责如下：

| 层次 | 职责 | 不承担的职责 |
|---|---|---|
| 执行提示词 | 全局安全约束、一级任务分类、少量跨工具参数规则 | 字段清单、详细报告格式、逐句路由案例 |
| 工具描述 | 说明工具产出、适用目标和明确的排除边界 | 重复完整参数定义 |
| JSON Schema | 参数名称、类型、枚举、必填项和字段级说明 | 自然语言意图分类 |
| Python 业务代码 | 查询、公式、阈值、状态语义和确定性报告 | 让模型补算业务结论 |
| 总结提示词 | 基于结构化工具结果解释和展示 | 重新路由、重新查询、覆盖 `report_content` |
| 路由评测集 | 用户目标到预期工具/参数的行为契约 | 把测试样本逐条复制进生产提示词 |

## 执行阶段设计

### 一级路由

执行提示词按“用户最终想得到什么”判断，而不是按是否出现 CGI、指标名或“小区”判断：

1. 用户要获取、查看、筛选、统计、分组、比较、排序、趋势、明细或导出数据，调用 `query_business_data`。
2. 用户要判断单小区是否有节电空间、能否扩展、是否需要收缩、休眠是否造成负荷影响，或要求节电建议，调用 `analyze_single_cell_energy`。
3. 用户要对一批小区执行同一节电诊断并导出，调用 `analyze_batch_cells_energy`。
4. 用户明确要求异常劣化判断、参数合规核查、固定口径能耗报告或小区名称解析时，分别调用对应专业工具。
5. 用户要求图表时，先用 `query_business_data` 取数，再调用 `generate_chart`。

同一句话同时包含“查询数据”和“据此判断节电空间”时，以最终诊断目标为准，调用专业节电分析工具。仅查询扩展表或收缩表中的字段、时段和距离仍属于数据读取，调用 `query_business_data`。

### 参数规则

主提示词只保留真正跨工具且模型必须知道的规则：

- 日期未提及时不推断日期。
- `query_business_data.question` 使用用户当前完整问题，不改写为 SQL。
- 用户明确要求 Excel 时向支持导出的工具传 `export_excel=true`。
- 单小区专业诊断按 CGI 或中文名定位；未说明诊断维度时使用 `analysis_target=all`。
- 禁止构造工具未返回的下载链接。

省市后缀、厂家归一化、各工具参数枚举等内容应优先放在对应 JSON Schema 或工具内部处理，避免在主提示词中重复。仍需模型执行且当前工具无法自行归一化的少量规则可以保留，但必须只出现一次。

## 工具描述设计

每个工具描述统一采用“产出 + 适用 + 不适用”的短结构，使边界在 function-calling 工具列表中直接可见。

`query_business_data` 的边界：

- 适用：读取授权物理字段和注册计算指标，包括单小区、多小区、多表、趋势、比较、排序和导出。
- 不适用：直接生成节电空间、扩展收缩决策、异常判定、参数合规结论或固定报告。

`analyze_single_cell_energy` 的边界：

- 适用：对一个 5G 小区做节电空间、扩展、收缩、周边负荷影响或休眠前负荷诊断。
- 不适用：仅查询字段值、指标值、表记录、明细或趋势。

其他专业工具也补充排除边界，避免“报告”“参数”“异常”等常见词造成职责重叠。工具参数的类型和枚举继续由现有 JSON Schema 提供，描述中不重复列举。

## 总结阶段设计

### 确定性报告

`analyze_single_cell_energy`、批量节电分析、参数核查和固定报告若返回非空 `report_content`，继续直接返回。业务章节、空数据语义、白名单三态和时段展示由 Python 保证，不依赖模型二次生成。

`SYNTHESIS_SINGLE_CELL` 仅保留旧版无 `report_content` 返回的兼容说明。若代码和运行环境已确认不再产生旧结构，可在后续独立变更中删除该兼容块；本次不冒险改变兼容行为。

### 结构化数据

`SYNTHESIS_BUSINESS_DATA` 只负责：

- 使用 `rows` 和 `columns` 回答用户所问的数据。
- 使用单位、粒度和 `metric_definitions` 解释口径。
- 在用户要求时基于已返回数据做比较或诊断，但不补数据、不改公式、不猜关联。
- 区分“查询成功但零行”和“查询失败”。
- 在数据质量不完整时降低结论强度并列出缺失字段。

执行提示词中的图表格式、报告章节和工具返回解释不再重复出现在无关总结提示词中。

## 典型行为契约

| 用户问题 | 预期工具 | 关键参数 |
|---|---|---|
| 查询5G小区460-00-2539193-71在2026年8月24日的深度休眠时长和深度休眠开关 | `query_business_data` | `question` 原样传入 |
| 查看这个小区2026年8月24日的扩展时段和周边小区距离 | `query_business_data` | `question` 原样传入 |
| 分析460-00-2539193-71在2026年8月24日有没有节电空间 | `analyze_single_cell_energy` | `cgi`、`stat_time`、`analysis_target=all` |
| 判断该小区是否还能延长休眠 | `analyze_single_cell_energy` | `analysis_target=expansion` |
| 查询最近7天能耗趋势并画折线图 | `query_business_data` 后接 `generate_chart` | 完整问题、完整查询结果 |
| 核查长沙市5G节能参数是否合规 | `query_energy_param_check` | 对应地域和网络参数 |

同一意图应增加不同表达方式作为评测样本，例如“帮我看一下”“取一下”“是多少”“有没有数据”等，但这些表达不写回生产提示词。

## 测试与验收

### 离线单元测试

- 断言执行提示词不再含有“查指标时调用对应业务工具”和已撤下单小区指标工具的遗留规则。
- 断言主提示词明确区分“字段/指标读取”和“节电决策”。
- 断言 `query_business_data` 与 `analyze_single_cell_energy` 的描述都具有正向适用范围和负向排除边界。
- 断言工具 JSON Schema 快照仍只暴露现有八个工具，参数结构不被提示词重构意外改变。
- 断言中间件仍按执行/总结阶段选用提示词，`report_content` 直出行为不变。

### 内网模型路由验收

使用生产同款内网模型批量运行路由评测集，记录工具名和 arguments，不访问生产业务表也可以完成第一阶段评测。最低验收标准：

- 所有“只查字段/指标”的样本均选择 `query_business_data`。
- 所有“节电空间/扩展收缩决策”的样本均选择对应专业工具。
- 查询问题原文完整进入 `question`，日期和 CGI 不被编造。
- 图表问题先查询再生成图表。
- 不出现已撤下的 `query_metric` 或 `query_cell_metric`。

如果职责重构后内网模型仍存在系统性误路由，再单独评估工具子集门控或两阶段路由；本次不提前引入额外延迟和复杂度。

## 发布与回退

本次只修改提示词、工具描述和测试，不新增依赖、不修改数据库。发布后重点观察工具调用日志中的 `tool_call_name`、arguments 和首次模型调用耗时。若实际路由准确率下降，可单独回退提示词提交，不影响数据查询和节电分析代码。
