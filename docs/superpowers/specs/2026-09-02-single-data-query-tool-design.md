# 单一数据查询工具设计

## 背景与问题

主智能体当前同时暴露 `query_cell_metric`、`query_metric` 和 `query_business_data` 三个数据查询工具。三者按“单小区固定指标”、“汇总固定指标”和“授权字段自助查询”划分，但用户问题可以同时包含固定指标和原始字段，导致工具意图重叠。

生产问题“查询深度休眠时长和深度休眠开关”被路由到旧 `query_cell_metric`；该工具又硬编码查询数据字典中不存在的 `cell_name` 和 `gnb_name`，最终触发 `UndefinedColumnError`。这不是单条路由规则缺失，而是数据查询接口重复。

## 目标

- 主智能体只暴露一个数据查询工具：`query_business_data`。
- 撤下并删除 `query_cell_metric` 和 `query_metric`。
- 保留两个旧工具的有效能力：单小区字段、汇总指标、分组、排序、Top N、Excel 和图表数据。
- 不再用“某句问法对应某工具”的方式扩充主提示词。
- 专业业务工具继续保留，不将节电诊断或固定报告降级成通用查数。

## 最终工具目录

Toolkit 最终只注册以下 8 个工具：

| 类别 | 工具 | 职责 |
|---|---|---|
| 数据查询 | `query_business_data` | 查询授权字段、确定性指标、分组、排序、Top N 和审核多表数据 |
| 单小区节电诊断 | `analyze_single_cell_energy` | 生成休眠扩展/收缩和高负荷等业务结论 |
| 批量节电诊断 | `analyze_batch_cells_energy` | 批量分析并导出业务报告 |
| 参数核查 | `query_energy_param_check` | 执行参数合规判断与核查清单导出 |
| 固定报告 | `query_report` | 生成既定口径和格式的 4G/5G 能耗报告 |
| 异常诊断 | `query_anomaly` | 按既定基线和阈值判断指标劣化 |
| 小区解析 | `resolve_cell_cgi` | 将中文小区名解析为 CGI |
| 可视化 | `generate_chart` | 把已查得的结构化数据转为 ECharts 配置 |

`query_cell_metric` 和 `query_metric` 不再出现于 Toolkit schema、执行提示词、总结提示词映射或测试夹具中。

## 数据查询能力迁移

### 单小区数据

`query_cell_metric` 的 6 类指标均是 `lte_report_day_detail` 或 `nr_report_day_detail` 中的物理字段：流量、载波关断时长、通道关断时长、符号关断时长、深度休眠时长和极致休眠时长。这些字段由 YAML 目录的中文名、别名和单位提供给 `query_business_data`，不再维护第二份小区指标枚举。

用户可在同一问题中组合任意授权字段，例如深度休眠时长和开关；查询计划只能使用实际 Schema 预热成功的字段，不得附加 `cell_name`、`gnb_name` 等未授权列。

### 汇总指标

`query_metric` 的能耗换算、流量换算和基站可读率已有新指标定义。迁移时还要覆盖月节电量等尚未对齐的确定性指标；原本就是数据库物理字段的小区数、基站数、开启率、生效总时长、节电率和平均能效继续直接查字段，不再伪装为第二份计算指标。

确定性指标注册是唯一计算口径。日报与数据自服务必须复用同一计算函数，不再保留 `REPORT_METRICS`、`CELL_METRICS` 和 `ALL_METRICS` 旧注册表。

### 分组、排序和 Top N

`query_business_data` 继续用结构化计划表达 `group_by`、`aggregations`、`order_by` 和 `limit`。迁移后必须支持：

- 按日期、地市、厂家、频段、站型或区域分组。
- 对数值物理字段执行 `sum`、`avg`、`min`、`max` 或 `count`。
- 按聚合别名排序并使用 `limit` 实现 Top N。
- 按确定性指标排序时，由指标注册提供可聚合的来源和口径，不让模型自由编写公式。

计算指标与分组同时出现时，数据库先按注册口径聚合来源字段，Python 再计算最终值。比例指标使用“聚合分子 ÷ 聚合分母”，不使用各行比例的简单平均。

## 图表数据链路

用户要求图表时，主智能体先调用 `query_business_data`，再把完整结构化返回传给 `generate_chart`。图表工具使用 `columns` 中的字段 ID、中文显示名和单位识别日期轴、维度和数值列，不假设 `rows` 一定使用英文键。

图表工具 schema 和错误信息中不再引用 `query_metric`。

## 主智能体意图边界

执行提示词只保留粗粒度业务分类：

- 只要用户目标是获取、筛选、分组、比较、排序或导出授权数据，就调用 `query_business_data`。
- 用户要求节电空间、异常劣化、参数合规或固定报告时，调用对应专业工具。
- 用户要求图表时，先获取数据，再调用 `generate_chart`。

主提示词不维护字段列表、指标枚举或逐句路由规则。字段和指标变更只修改目录与确定性指标注册。

## 错误处理与运行配置

- 不存在、未授权或存在歧义的字段在执行 SQL 前返回澄清信息。
- 查询计划只能使用目录快照中已核验的物理字段和关系。
- 撤下旧工具后不做隐式 fallback；通用数据查询失败时明确告知查询或配置问题。
- 生产环境必须设置 `SELF_SERVICE_ENABLED=true` 和独立只读 `SELF_SERVICE_DATABASE_URL`。
- 本次迁移不新增 Python 依赖；仍使用已明确告知的 `PyYAML==6.0.3`。

## 测试与验收

单元测试验证工具目录、Schema 白名单、指标公式、SQL 构造、粒度、分组、排序、Top N、质量信息和图表兼容性。不再用“提示词必须包含某句中文示例”作为意图识别测试。

验收问题至少覆盖：

1. `查询5G小区460-00-2539193-71在2026年8月24日的深度休眠时长和深度休眠开关。`
2. `查询2026年8月24日各5G地市的流量，按流量从高到低取前5名。`
3. `查询长沙市5G网络最近7天的能耗趋势并生成折线图。`
4. `查询小区460-00-2539193-71的扩展时段、需收缩时段和周边小区距离。`
5. `分析小区460-00-2539193-71的节电空间。`

前 4 题的取数阶段只能调用 `query_business_data`；第 3 题随后调用 `generate_chart`；第 5 题调用 `analyze_single_cell_energy`。Toolkit schema 中不存在 `query_cell_metric` 或 `query_metric`。

全量离线测试必须通过。内网模型路由验收使用一组多样表达进行批量评测，不将每个样本反向写入主提示词。
