# 多轮能效查询防编造与扩展档位提示设计

## 背景

当前会话持久化只保存用户问题和最终回答，不保存对应的工具调用和数据证据。新请求又会把旧回答原样注入 Agent 上下文，因此多轮后模型可能把旧数字或旧结论当作本轮证据，在没有重新查询的情况下直接回答。

另外，节电扩展报告只在保守扩展时提示其他档位，中等扩展和激进扩展缺少对称的可选项提示。

## 目标

- 凡涉及具体数据、判断或结论的当前请求，必须在本轮重新调用工具获取证据。
- 历史回答只用于前端展示，不作为新一轮数据证据。
- 保留历史用户问题，以支持“再看中等扩展”“换成激进扩展”等指代和条件复用。
- 保守、中等、激进三种扩展报告都提示另外两种可查询档位。
- 不修改现有业务表、对外 API 协议和报告核心口径。

## 方案

### 1. 历史证据隔离

消息适配层继续解析完整的会话历史，但只把历史 `user` 消息放入 Agent 的执行上下文，不把历史 `assistant` 回答放入模型上下文。数据库中的会话记录不删除、不改写，前端仍可完整展示。

这个边界确保：

- “上一轮查了哪个小区”可以从历史用户问题中恢复。
- “上一轮回答的数字”不会出现在新一轮执行上下文中。
- 若用户要求比较或重看结论，Agent 必须重新查询所需数据。

### 2. 首次推理强制工具调用

在 AgentScope reasoning middleware 中增加本轮证据门禁：

- 本轮尚无工具结果时，向模型传入 `ToolChoice(mode="required")`，并将业务请求的可选工具限制为业务工具，禁止直接产生文本答案或选择通用兜底。
- 工具已返回后，恢复现有 ReAct 流程；支持报告直出的工具仍由现有 `DirectAnswerMiddleware` 返回。
- 数据工具失败时，只返回当前失败原因，不从历史回答补数据。

为避免寒暄、能力说明或需求不明时被迫调用业务数据工具，工具集新增一个无参数的安全兜底工具。该工具只能返回代码中固定的能力说明或“请具体说明查询需求”，不接收、生成或返回任何业务数字。仅当当前问题精确匹配受控的寒暄或能力询问时，代码才强制路由到该工具；其他请求不向模型暴露该工具。

### 3. 扩展档位提示

复用 `app/services/expansion_levels.py` 中的中央映射，根据当前 `expansion_level` 动态排除已选档位，生成其余两个档位的提示。单小区和批量报告共用同一个格式化函数，避免两处硬编码再次不一致。

期望文案：

- 保守扩展：提示中等扩展（400M）和激进扩展（500M）。
- 中等扩展：提示保守扩展（300M）和激进扩展（500M）。
- 激进扩展：提示保守扩展（300M）和中等扩展（400M）。

只有报告包含扩展分析时才显示该提示；纯收缩、休眠前负荷等报告不显示。

## 数据流

1. API 读取持久化会话和当前用户问题。
2. 消息适配层保留历史用户问题，隔离历史助手回答。
3. 请求级 Agent 进入首次推理，证据门禁强制选择工具。
4. 业务问题调用相应数据或诊断工具；非数据问题调用固定兜底工具。
5. 工具结果按现有直出或结果解读流程返回。
6. API 仍按现有方式保存当前用户问题和最终回答。

## 异常处理

- 本轮数据工具查询失败或无数据：原样反映工具状态，不使用上一轮结果。
- 模型路由到非数据兜底工具：返回固定、不含业务数据的文本。
- 未提供扩展档位：保持现有默认保守扩展规则，提示中等和激进扩展；显式传入未登记档位时继续拒绝。
- 强制工具调用时模型返回协议错误：由现有 AgentScope 错误事件和 API 终止流程处理，不持久化不完整答案。

## 测试

- 消息适配测试：历史用户消息保留，历史助手消息不进入 Agent context，当前问题仍正确分离。
- 运行时测试：首次 reasoning 使用 `ToolChoice(mode="required")`，本轮获得工具结果后不再强制。
- 兜底工具测试：返回固定文本，输出中不包含任何业务数据。
- 单小区报告测试：三个档位分别显示另外两个档位。
- 批量报告测试：三个档位分别显示另外两个档位，且纯收缩报告不显示。
- 回归测试：运行现有完整测试集，确认 Dify 流式/阻塞协议、工具直出、对话持久化和三档表路由不受影响。

## 不在本次范围

- 不新增工具调用快照表或会话证据审计表。
- 不复用上一轮工具结果，不做数据缓存。
- 不调整节电扩展、收缩或负荷判断的业务口径。
- 不改变会话历史在前端的展示方式。
