# 节电稀疏结果语义、报告字段与查询性能设计

日期：2026-08-25

状态：已确认，待实施

## 目标

修正单小区节电报告对空扩展、空收缩结果的业务语义，将无结果记录解释为“各维度均未满足条件”，而不是“没有数据”或“缺少证据”。报告按需展示可复核的过程数据，并使用业务 CSV 第二行提供的中文字段名。同时减少无效明细查询，为生产高频查询增加复合索引脚本。

## 生产证据与根因

`origin/error` 的 `error/0825test.txt` 显示：

- 总耗时 `114426.21ms`；
- 报告渲染仅 `0.12ms`；
- 扩展查询 `46533.76ms`；
- 参数核查 `50392.34ms`；
- 运行明细查询 `62268.31ms`。

报告格式不是主要耗时点。当前实现无论是否存在候选时点，都会并发执行 `jd_cell_detail_hour_nr` 的全量夜间近 15 天聚合，且缺少能约束 CGI、日期与小时的组合索引。新流程仍保留“无候选时展示全部 10 个分析时点”的解释能力，但有候选时只查询候选小时，并通过索引降低两类查询成本。参数核查与运行明细耗时大幅波动，说明还需要补齐 CGI 与日期组合索引。

## 业务语义

### 扩展结果

`jd_cell_expansion_day` 是稀疏的正向结果表：只要任一扩展维度存在空间，表中就会有记录。

- 查询成功且无记录：各扩展维度均未满足，对外结论固定为“经过智能体分析，该小区没有可以扩展的时段。”
- 有记录但 `hour_filter` 和 `hour_filter_early` 都没有小时：可能存在其他维度的空间，但没有可扩展时段；报告仍使用上述固定结论，保留其他已返回字段作为依据。
- 任一时窗有小时：显示可扩展候选和部署时段。
- 数据库查询异常：才能进入 `unavailable`，不得输出否定性结论。

### 收缩结果

`jd_cell_constriction_day` 同样是稀疏的正向结果表。

- 查询成功且无记录：该小区没有需要收缩的节电时段。
- 有记录：按收缩时点展示主小区、关联范围、周边小区负荷变化和收缩建议。
- 无记录时不再输出四个“未获得证据”的空标题。

### 白名单

- 扩展或收缩任一来源明确返回“是”：白名单小区，展示原因和有效期。
- 查询链路正常且未命中白名单：直接写“该小区不是节电白名单小区。”
- 只有白名单来源查询异常或返回无法解析的脏值时，才输出暂无法判断。

## 字段展示规则

字段英文名以 CSV 第一行为准，报告列名以 CSV 第二行为准。报告不直接显示英文字段名。为避免一张超宽表，字段按业务用途分组；同一字段不在多张表重复。

### 基础信息

扩展和收缩共用以下字段，在报告基础信息中展示：

| 英文字段 | 报告中文名 |
|---|---|
| `stat_time` | 统计开始日期 |
| `dist_name` | 地市名称 |
| `county_name` | 区县名称 |
| `prod_name` | 厂家 |
| `gnb_name` | 基站名称 |
| `cell_name` | 小区名称 |
| `cgi` | CGI |
| `work_band` | 频段 |
| `cover_type` | 覆盖类型 |
| `cover_scen` | 覆盖场景 |
| `site_type` | 站型 |

| 英文字段 | 报告中文名 |
|---|---|
| `hour_detail` | 可扩展休眠小时详情 |

| `hour_filter_early` | 未休眠可扩展时段小时列表(仅夜间常规时段) |

| `deploy_hours_continuous` | 含已休眠连续部署时段(含扩展时段) |
| `deploy_hours_early` | 含已休眠部署时段_不连续(仅夜间常规时段) |
| `deploy_hours_continuous_early` | 含已休眠连续部署时段(仅夜间常规时段) |

`hour_detail` 中的低业务占比与 `jd_cell_detail_hour_nr` 的近 15 天平均休眠时长合并为“低业务与休眠情况分析”：

- 存在可扩展时点时，只展示最终命中的可扩展时点。
- 不存在可扩展时点时，展示 22、23、0 至 7 点全部 10 个分析时点，逐行说明低业务条件未满足、已有休眠或指标不完整。
- 指标不完整的时点保留在“无候选”表中，但只标记为“未进入候选结果”，不得把缺失值替换为 0。
- 最终扩展结论始终由扩展结果表决定，过程表只用于解释。

## 单小区报告结构

1. 概览结论：小区与日期、扩展时段结论、收缩结论、参数核查、白名单状态。
2. 基础信息：公共字段使用一行横向表格，只展示已返回的列。
3. 休眠扩展，固定顺序为：扩展结论、容量与风险说明、低业务与休眠情况分析、横向扩展结果明细、连续部署结果、参数核查、综合扩展建议。扩展结果明细的第一行是中文列名，第二行是数据，不使用“字段中文名称/结果”纵向形式。容量状态为高负荷时，明确提示先压降再扩展。
4. 休眠收缩严格分为两部分：
   - “周边 200 米关联小区高负荷影响判断”：先展示 `sleep_hour` 提供的当前已生效休眠时点，再展示主小区休眠条件、关联范围、关联小区负荷变化和需剔除的原节电时段。不计算或展示“调整后完整节电时点”。
   - “休眠生效前高负荷分析”：独立展示休眠前一小时负荷明细、近 7 天高负荷天数和持续风险结论，不与周边小区表混排。
5. 白名单：未命中时直接说明不是白名单小区；命中时展示原因和有效期。

当扩展、收缩及过程查询均成功但结果为空时，报告仅保留基础信息、无可扩展时段结论、无需剔除原节电时段结论、休眠生效前未发现持续高负荷结论、参数核查和白名单结论；不生成空表或“未获得证据”标题。

## 批量导出结构

- 仅查扩展：Excel 仅包含“扩展明细”，按扩展 CSV 的 23 个字段顺序导出。
- 仅查收缩：Excel 仅包含“收缩明细”，按收缩 CSV 的 25 个字段顺序导出，并在最后补充 `distance`、`around_site_type`。
- 同时查扩展和收缩：Excel 包含三个工作表：
  - “小区汇总”：一个 CGI 一行，展示基础信息、扩展时段、两套连续部署结果、收缩记录数、需收缩时点、受影响关联小区数、最大 PRB 抬升量和白名单状态。
  - “扩展明细”：保留扩展原表的一小区一行结构。
  - “收缩明细”：保留“主小区 × 收缩时点 × 受影响关联小区”一行的结构，通过 CGI 与汇总表关联。
- 不再导出“休眠前高负荷”工作表，但相关统计仍可用于聊天概览。
- 所有工作表冻结首行、开启自动筛选，按 CGI 稳定排序；报告列名使用 CSV 第二行中文名称。

报告不向用户暴露“数据库预计算”、“稀疏结果表”或内部状态枚举。

## 查询流程与性能

### 应用查询裁剪

1. 并发查询扩展结果、收缩结果和参数核查。
2. 扩展结果有候选时点时，15 天休眠聚合只查询候选小时；无候选时点时，查询 22、23、0 至 7 点全部 10 个小时以解释未命中原因。
3. 扩展结果查询和休眠聚合拆分记录耗时，并仅选择报告需要的列。
4. 收缩结果为空时，不查询邻区关系和工参站型。
5. 参数核查已传入明确日期时，不再执行 `MAX(check_time)`。
6. 休眠前近 7 天高负荷天数在 SQL 中聚合，避免返回无需展示的全部候选行。

### 索引脚本

仓库新增可独立执行的 PostgreSQL 索引 SQL，使用 `CREATE INDEX CONCURRENTLY IF NOT EXISTS`，不由应用启动时自动执行：

- `jd_cell_expansion_day (cgi, stat_time)`；
- `jd_cell_constriction_day (cgi, stat_time)`；
- `jd_cell_detail_hour_nr (cgi, stat_time, hours)`；
- `jd_cell_pre_hour_busy (cgi, stat_time)`；
- `eng_check_result (cgi, check_time)`；
- `jd_cell_around (cgi, around_cgi)`。

索引脚本作为生产部署步骤，应在 PostgreSQL 会话中逐条执行，不包在显式事务中。

### 耗时日志

保留总阶段耗时，并将慢阶段继续拆分为：

- 扩展结果查询；
- 扩展休眠明细聚合；
- 参数日期解析；
- 参数明细查询；
- 休眠前当日明细；
- 休眠前近 7 天统计。

耗时字段仅进入结构化日志和工具 `performance`，不进入用户报告。

## 错误处理

- 成功的空查询是业务结论，不是错误。
- SQL 异常、连接超时或脏值无法解析时，保留“暂无法判断”状态，禁止伪造否定性结论。
- 各并发阶段的异常应包含阶段名、CGI 和查询日期，但不在用户报告暴露 SQL 或内部堆栈。

## 测试与验收

1. 扩展结果成功返回空集时，固定结论为“经过智能体分析，该小区没有可以扩展的时段”。
2. 有扩展记录但无候选小时时，使用同一结论，但保留其他已返回字段。
3. 有候选时点时，低业务与休眠表只显示命中时点；无候选时点时展示全部 10 个分析时点及未命中原因。
4. 收缩结果为空时，报告说明无需收缩且不展示空过程标题。
5. 单小区扩展明细横向展示；报告和 Excel 的扩展、收缩列名与两份 CSV 第二行一致，所有新增字段均可见。
6. `distance`、`around_site_type` 继续从关系表和工参表补齐；默认距离规则为 200 米，`prb_increase = 10.0` 记录保留。
7. 正常未命中白名单时明确输出“不是节电白名单小区”；查询异常不得输出未命中结论。
8. 已知日期的单 CGI 参数核查不再调用最新日期查询。
9. 索引 SQL 覆盖六组生产查询键，可重复执行且不包含事务包装。
10. 批量仅扩展、仅收缩和同时查询分别生成 1、1、3 个规定工作表，汇总表一个 CGI 一行，收缩明细保留一对多关系。
11. 单元测试、报告渲染测试、工具并发测试和全量回归测试全部通过。
