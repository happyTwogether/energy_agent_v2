# 节电扩展三档策略接入设计

## 1. 目标

在现有节电扩展能力中增加中等扩展和激进扩展两档，使单小区诊断、批量分析与 Excel 导出、通用业务数据查询都能按用户指定的低业务流量门限读取对应结果表。

三档策略的低业务判断窗口均为不少于 15 天，低业务占比均为不少于 90%，仅小时流量门限不同：

| 策略 | 流量门限 | 扩展结果表 |
|---|---:|---|
| 保守扩展 | 低于 300M | `jd_cell_expansion_day` |
| 中等扩展 | 低于 400M | `jd_cell_expansion_day_400` |
| 激进扩展 | 低于 500M | `jd_cell_expansion_day_500` |

用户未明确指定策略时默认使用保守扩展。默认结果必须提示还可选择中等扩展或激进扩展；用户在后续对话中指定其他策略时，复用当前小区或批量筛选条件，并改查对应结果表。

## 2. 设计原则

- 三张扩展结果表字段一致，共用现有解析、证据组装、统计、报告和导出逻辑。
- 扩展策略通过受控枚举传入，表名仅由代码内固定映射产生，不接受用户直接提供 SQL 表名。
- 策略只影响扩展结果来源；收缩分析、休眠过程证据、参数核查、关联小区分析和报告规则保持不变。
- 单小区、批量和通用数据查询使用一致的策略含义和默认值。
- 报告明确展示实际使用的策略和业务门限，避免用户误将不同策略结果混用。

## 3. 工具接口与路由

### 3.1 统一策略枚举

单小区节电工具和批量节电工具新增可选参数 `expansion_level`：

- `conservative`：保守扩展，默认值；
- `moderate`：中等扩展；
- `aggressive`：激进扩展。

工具内部维护不可变元数据，包括枚举值、中文名称、流量门限和数据库表名。所有扩展 SQL 均从该映射取得表名。Schema 使用枚举约束，函数层仍对缺省或非法值做防御性归一化，确保无法构造任意表名。

### 3.2 Agent 参数归一化

Agent 执行提示增加以下映射：

- “保守扩展”“300M”“低于 300M”映射为 `conservative`；
- “中等扩展”“400M”“低于 400M”映射为 `moderate`；
- “激进扩展”“500M”“低于 500M”映射为 `aggressive`；
- 未出现档位或门限时映射为 `conservative`。

后续追问如“再看中等扩展”应结合对话上下文复用此前的 CGI、小区名称、日期或批量区域条件，并使用新的 `expansion_level` 重新调用对应工具。模型不得根据三档结果自行推算或改写扩展时段。

### 3.3 日期与查询一致性

单小区仅扩展查询使用所选扩展表的最新日期；全量分析使用所选扩展表与收缩表共同可用的最新日期。批量分析的扩展日期和扩展明细也全部来自所选扩展表，避免日期来自保守表而数据来自其他表。

现有高负荷基础信息、白名单信息和扩展明细若来自扩展表，也必须统一切换到所选表。休眠小时级证据仍读取 `jd_cell_detail_hour_nr`，其 15 天窗口算法不变。

## 4. 输出行为

单小区和批量结果增加稳定的策略元数据，至少包含策略枚举、中文名称和流量门限。确定性报告在扩展章节或概览附近显示本次策略，例如“本次采用保守扩展（低于 300M 概率不低于 90%，观察不少于 15 天）”。

采用保守扩展时，报告末尾提示：“还可选择中等扩展（400M）或激进扩展（500M）查看对应结果。”这样即使 Agent 显式传入默认枚举，提示行为仍然确定。采用中等或激进扩展时只说明当前策略，不重复该提示。

批量 Excel 保持现有工作表结构和字段顺序；文件结果与聊天汇总都携带策略说明，确保导出文件可辨认其数据口径。除策略说明外，扩展明细字段保持三份 CSV 的共同结构。

如果用户只做收缩或休眠前负荷分析，`expansion_level` 不改变结果，也不展示无关的扩展策略提示。

## 5. 通用业务数据查询

业务数据目录新增 `jd_cell_expansion_day_400` 和 `jd_cell_expansion_day_500` 两张表，字段定义与现有 `jd_cell_expansion_day` 相同，但使用彼此可区分的标签、描述和别名：

- 现有表突出“保守扩展、300M”；
- 400 表突出“中等扩展、400M”；
- 500 表突出“激进扩展、500M”。

新表复制扩展表与收缩结果、小时明细、休眠前负荷、工参和参数核查之间的既有关系，使自然语言查询能够使用原有连接能力。泛称“扩展表”仍优先指向默认保守表；只有明确出现中等、激进或对应门限时才选择新表。

## 6. 单小区与批量实现边界

### 6.1 单小区

- 所选扩展表参与最新日期、扩展结果、高负荷基础信息和白名单判断。
- 现有扩展状态、候选时段、连续部署时段、过程证据和报告章节不重算，仅消费所选表结果。
- `analysis_target=all` 时仅扩展半侧切换表，收缩半侧保持原表。

### 6.2 批量

- 批量工具新增同一 `expansion_level` 参数，所有扩展 SQL、最新日期选择、统计和导出明细统一读取所选表。
- `analysis_target=all` 和 `analysis_target=expansion` 支持三档；仅收缩查询不因扩展档位发生变化。
- 批量报告和导出返回值记录所选策略，避免下载后丢失口径。

## 7. 错误处理与安全

- Schema 层拒绝非法 `expansion_level`；函数被直接调用且收到非法值时返回参数错误。任何非法值都不得静默回退，也不得参与 SQL 表名拼接。
- 所选表无数据时沿用现有“暂无节电分析数据”或空结果语义，不自动回退到其他策略表，以免口径悄然变化。
- 三档表的字段若与共同契约不一致，数据库错误按现有工具错误机制返回并记录日志，不通过猜测字段修复结果。
- 日志增加扩展策略和实际表标识，便于定位生产问题；对用户不暴露 schema 等内部数据库细节。

## 8. 测试与验收

### 8.1 单元与集成测试

1. 单小区工具 Schema 和函数默认使用 `conservative`。
2. 三个枚举分别生成对 `jd_cell_expansion_day`、`jd_cell_expansion_day_400`、`jd_cell_expansion_day_500` 的查询。
3. 最新日期、高负荷基础信息、白名单和扩展详情均使用同一所选表。
4. `analysis_target=all` 切换扩展表但不改变收缩表。
5. 批量扩展和全量分析按档位查询、统计并导出对应数据；仅收缩流程保持不变。
6. 报告展示当前策略；默认保守结果提示另外两档可选，中等和激进结果不伪装成默认结果。
7. Agent 提示正确覆盖中文策略名和 300M/400M/500M 表达，未指定时采用保守档。
8. 业务数据目录能按三档关键词检索到正确表，新增关系可通过目录校验。
9. 非法枚举不能影响 SQL 表名。

### 8.2 验收示例

- “分析这个小区的节电空间”：查询保守表，报告显示保守扩展并提示中等、激进可选。
- “再看中等扩展”：复用上一轮对象，查询 400M 表并显示中等扩展口径。
- “按长沙市批量分析激进扩展并导出”：查询 500M 表，聊天统计与 Excel 明细均来自激进扩展结果。
- “查询 400M 扩展表的连续部署时段”：通用业务数据查询选择中等扩展表。

## 9. 非目标

- 不修改后台三张结果表的数据生产算法或表结构。
- 不在应用层重新计算 300M、400M、500M 命中结果。
- 不改变收缩、参数核查、休眠前负荷和关联小区的业务阈值。
- 不把三档结果合并为一个“最优”时段，也不自动比较后替用户选择策略。
