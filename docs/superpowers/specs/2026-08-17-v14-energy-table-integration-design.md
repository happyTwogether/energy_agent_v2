# V1.4 节电扩展与收缩结果接入设计

日期：2026-08-17

状态：业务口径已确认，待实施

## 1. 目标

在当前生产使用的 AgentScope `app/` 链路中接入 `jd_agent` 已预计算的 V1.4 节电扩展、节电收缩字段，补齐单小区完整报告、休眠前负荷闭环、批量统计和 Excel 原始整表输出。数据库预计算结果是业务结果源，应用负责结果读取、关系补充、边界防御和报告组装，不再维护第二套扩展或收缩算法。

本阶段完成旧生产链路和验收测试。Durable A2A/MCP 迁移在旧链路行为稳定后复用本设计中的纯业务结果模型，不在本阶段切换生产运行时。

## 2. 已确认的业务口径

### 2.1 扩展结果

`jd_cell_expansion_day` 的下列字段直接作为 V1.4 结果，不在 Python 中重新计算：

- `hour_detail`
- `hour_filter`、`hour_int`
- `hour_filter_early`、`hour_int_early`
- `deploy_hours`、`deploy_hours_continuous`
- `deploy_hours_early`、`deploy_hours_continuous_early`

数据库结果已经采用 22、23、0 至 7 点共 10 个目标小时，并覆盖 `low_flow_pct >= 90%` 的边界。应用不得继续使用旧的 `low_flow_pct > 90%`、休眠均值 `< 60 秒` 或包含 8 点的本地算法覆盖数据库结果。

### 2.2 收缩结果

`jd_cell_constriction_day` 的主小区休眠前 PRB、休眠时长、邻区休眠前后 PRB、负荷抬升量和休眠前时间字段直接作为收缩证据：

- `self_prb_rate_ul_before`、`self_prb_rate_dl_before`
- `self_sleep_duration`
- `prb_rate_ul`、`prb_rate_dl`
- `prb_rate_ul_before`、`prb_rate_dl_before`
- `prb_increase`
- `before_sleep_hour`、`before_sleep_date`
- `around_cgi_network_type`

数据库结果中的 `prb_increase = 10.0` 记录必须保留。应用不按需求文档中的严格 `> 10%` 再次过滤预计算结果。

### 2.3 距离与站型

距离来自 `jd_cell_around.distance`。站型来自工参表：5G 使用 `nr_fix_prm.site_type`，4G 使用 `lte_fix_prm.site_type`。

主小区站型优先采用 `jd_cell_constriction_day.site_type`；该字段为空时，通过主小区 CGI 批量查询最新 `nr_fix_prm` 记录兜底。邻区根据 `around_cgi_network_type` 的 `nr` 或 `lte` 值，按 CGI 批量查询对应工参表的最新站型。

关联规则如下：

- 宏站主小区：保留 200 米内的宏站邻区。
- 室分主小区：保留 100 米内的宏站和室分邻区。
- 微站主小区：暂按 200 米；为避免在文档无明确站型限制时误删数据库结果，不额外限制邻区站型。

如果关系表或工参表无法补齐距离、主小区站型或邻区站型，保留数据库预计算结果，在证据中标记“关系信息缺失”并记录结构化警告，不静默丢弃结果。

## 3. 组件与数据流

### 3.1 结果模型与纯业务规则

新增小型、无数据库依赖的结果组装模块，负责：

- 规范化 `lte/nr` 与 `4G/5G` 网络标识。
- 根据主小区站型返回距离阈值。
- 判断已补齐关系信息是否满足站型和距离规则。
- 将扩展、收缩、休眠前负荷行转换为稳定的原始表字段。
- 保留 `prb_increase = 10.0`。

规则函数只接收显式参数，不读取全局 session，便于单元测试和后续 MCP 复用。

### 3.2 数据访问

单小区分析按以下批次读取数据：

1. 查询 `jd_cell_expansion_day` 或 `jd_cell_constriction_day` 的目标小区和日期结果。
2. 对收缩结果中的所有 `(cgi, around_cgi)` 组合一次性查询 `jd_cell_around`，获得距离与邻区网络类型。
3. 将主小区 CGI 和邻区 CGI 按网络制式分组，分别批量查询 `nr_fix_prm`、`lte_fix_prm` 最新工参。
4. 在 Python 中组装证据和展示字段，不执行逐行数据库查询。

所有集合查询使用参数绑定；不得拼接 CGI、日期或筛选值，不引入 N+1 查询。

### 3.3 单小区输出

`analyze_single_cell_energy` 保持现有工具名和输入契约。

- `expansion`：返回数据库原始扩展字段和易读摘要表。
- `constriction`：返回数据库原始收缩证据、距离、主小区站型、邻区站型和易读摘要表。
- `all`：同时返回扩展、收缩、参数核查、休眠前负荷和白名单信息。
- `constriction`：除收缩结果外同时返回休眠前负荷和七日高负荷天数。
- `pre_sleep_load`：继续支持独立子问题。

单小区原始结果默认生成完整 Markdown 表；超过 50 行时，聊天仅显示前 50 行并同时生成完整 Excel。返回结构明确给出总行数、展示行数、是否截断和下载地址。

### 3.4 批量输出

批量分析支持区县、地市和全省范围：

- “总计分析小区数量”在过滤问题小区之前按去重 CGI 计算。
- 汇总高负荷、可扩展、参数不合规、需要收缩、邻区压力、休眠前高负荷和白名单小区数。
- 休眠前七日统计限定开始和结束日期，并只统计满足休眠前一小时关系且 PRB 超过 50% 的日期。
- 聊天返回汇总；完整扩展、收缩证据和新增字段写入 Excel。
- 正常小区不从完整 Excel 中删除；可在问题清单中单独筛选。

## 4. 导出与提示词

统一 Excel 字段映射增加 V1.4 扩展和收缩字段的中文标题。原始数值保持数值类型，CGI、小时列表和连续部署时段保持文本类型。

Agent 提示词停止解释旧的 `> 90%`、`< 60 秒` 本地算法，改为说明结果来自数据库预计算口径。提示词必须要求：

- 扩展子问题展示连续部署时段、含扩展时段和仅常规时段结果。
- 收缩子问题展示主小区休眠前负荷、邻区休眠前后 PRB、抬升量、距离和双方站型。
- 完整分析包含休眠前高负荷表和建议。

## 5. 错误与兼容处理

- 查询不到目标日期时沿用现有最新公共日期回退规则，并返回日期说明。
- 预计算结果存在但关系补充缺失时保留结果，不伪造距离或站型。
- JSON、小时列表或数值字段异常时只降级对应字段，记录日志并继续返回其余可用证据。
- 保留现有工具名、输入 Schema 和主要返回键，新增字段采用向后兼容方式加入。
- 旧字段 `is_highload`、`saving_switch_state`、`starttime`、`endtime`、`reason` 和 `is_whitelist` 已确认仍在数据库中，现有查询可继续使用。
