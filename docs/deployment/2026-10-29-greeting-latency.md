# 已识别问候语提速：完整部署包 v6

本包保留当前已恢复服务的全部更新，只修正已识别固定说明请求仍等待模型的问题。不调整 .env、模型网关、镜像或容器网络。

生产截图中“你好”的上下文检查仅1.14ms，模型调用14298.02ms，输入3865 tokens、输出222 tokens并生成一次工具调用。旧代码已经将其限定为固定能力说明工具，却仍让模型输出已确定的调用，因此白等了一次模型往返。日志无法区分模型排队、预填充及生成各自耗时。

本版复用现有路由和 ExecutionPolicy，已识别的完整短句在原生 Toolkit 内本地执行，远程模型调用0次，保留事件、消息和会话状态保存。问候这一轮的摘要压缩延后到下一轮需要模型的业务请求；带真实业务目标的“你好，请分析……”仍走分析，不能当作纯问候。

## 部署一次即可

将 `energy问候提速-20261029-v6.zip` 总文件放到原项目目录，执行这一行：

```sh
unzip -o energy问候提速-20261029-v6.zip -d update-v6 && bash update-v6/部署更新.sh
```

总包解出后的所有文件需放在同一目录，分包 ZIP 由脚本处理。脚本先校验并备份，完整替换 app/scripts 与 main.py/chat.html/清单，然后 stop/start 现有 `energy` 容器；保留实际配置、网络、数据库、日志、导出和业务目录。数据库分包保留原建表/授权脚本，本次不新增表，也不自动执行 SQL。

部署后在原页面输入“你好”。日志应出现 `fixed_guidance_local tool=answer_general_guidance remote_model_calls=0`，对应模型阶段 token 为0。AgentScope 仍可能记录逻辑模型阶段事件，这不代表访问了远程模型。数据库读取、保存和页面传输仍有耗时，不能保证生产端到端等于本地计算耗时。

结果自动保存到 `update-v6/部署结果.txt`；脚本只有数据库会话表检查通过才输出就绪。接着验证湘潭→株洲→中等扩展等正常业务即可。
