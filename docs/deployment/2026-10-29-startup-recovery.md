# 更新内容继续部署：启动恢复修复版

本包保留此前地区约束、连续追问、摘要持久化、用户隔离等更新，新增数据库启动恢复处理。不是回退包。使用这份说明，不再重复执行 v4 的整套手工操作。

## 你只需做这些

1. 把总包传到远端，完整解压到一个单独文件夹，例如原项目的 `update-v5`。分包 ZIP 保留，部署脚本会自动解压。
2. 在解出的文件夹内执行一次：

   ```sh
   bash 部署更新.sh
   ```

3. 打开原聊天页面观察状态，正常进入后按原会话验证“湘潭市的节电空间”→“株洲市的呢？”→“中等扩展”。

脚本识别现有 `energy` 容器绑定的真实项目目录，使用现有镜像先校验待部署文件；通过后备份、完整替换 app/scripts 与 main.py/chat.html/清单，停止并启动原容器。不会重建容器，不调整网络、镜像、Compose、`.env`、数据库、业务目录、日志或导出文件。完整 app 分包可以单独查看和传输；使用自动部署时，不用再手动删除目录。

部署结果自动写到本文件夹的 `部署结果.txt`。如果仍有问题，只需带回这一个文件，无需再传多条排查命令。不要覆盖掉同一文件夹的这份结果；再次尝试前另存文件或换一个解包目录。

## 这次具体修复

- 原版在启动中连接数据库失败后，异常直接使整个进程退出。本版一次检查最长5秒；未就绪时每5秒自动重试，正常后每30秒复查。
- HTTP 页面在数据库未就绪时仍可打开，页面显示实际状态，依赖恢复后自动开放发送。查询、会话列表等业务 API 在未就绪时返回503，不调用模型、不伪造成功，不关闭持久化。
- 已存在的状态表仍须正确建好、授权。检查恢复后即可自动继续，无需仅为了让程序重新检查而再重启；修改实际连接配置仍需重启。
- 自助目录预热在数据库检查通过后执行，不阻断专业工具。后台检查任务在进程关闭时取消，不遗留后台连接检查。

## 怎样判断是否完成

脚本会自动等待最多60秒：

- 输出 `PASS 新版 HTTP 与数据库会话表检查已就绪`：连接和会话表读取检查通过。继续在页面验证真实查询、Excel、保存和重启后的追问。
- 输出 `NOT_READY`：源码已更新，但业务依赖尚未通过；进程继续重试，页面显示原因。不能把这一结果视为业务恢复，也不需要重复替换相同代码。

持续的 TCP 超时仍会阻止查询。这份代码修复启动退出和无法自动恢复的问题，不能替代目标环境实际建立数据库连接。健康检查也不代表已经验证模型、写权限、行级策略和所有业务表。

已有建表和授权脚本附在数据库分包，仅在缺表/授权不足时由管理员按需执行；部署脚本不运行 DDL，不申请 CREATE 权限。

## 文件与备份

`app完整.zip` 包含全部 app 源文件；`scripts完整.zip` 包含全部可部署脚本；根目录分包只有 main.py、chat.html 和 patch-manifest.json。实际配置及凭证不放进代码包。

脚本在修改前自动建立同级 `energy-before-update.*` 备份目录，输出其位置。校验失败时不停止原容器，也不替换生产源码。若停止后发生磁盘或文件权限等错误，脚本会退出并把停止位置记入结果文件，不自动将半套代码视为部署完成。
