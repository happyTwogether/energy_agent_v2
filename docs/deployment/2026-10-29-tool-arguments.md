# v7：原生工具参数校验与干净重试

本包包含此前全部更新和问候提速，可直接替换当前版本，不需要先安装 v6。数据库、模型网关、.env 和现有容器网络不调整。

## 为什么同样问题有时成功、有时失败

用户日志中的三次“分析湘潭市的节电空间”均为 cid 为空的新对话。首次调用批量分析、导出并保存成功；之后两次在模型返回一个工具调用后，没有进入业务工具，随后的第二次模型请求被网关以 `Expecting value: line 3 column 1 (char 2)` 拒绝。不是重复提问限制，也不是这三次请求的会话摘要恢复失败。

安装的 AgentScope 会尝试解析/修复工具参数，解析失败时把工具错误反馈给下一次推理；OpenAI 格式器会把原 assistant 工具参数原样发回。使用空白参数 `\n\n`，本地已复现相同的第二次请求400路径。原生产日志没有记录参数原文，所以不能声称已逐字确认实际坏参数。

修复在共同模型边界校验完整原生 ToolCallBlock 的参数必须为 JSON 对象。流式参数只检查完整响应，不检查半截分块。无效响应不进入工作历史、不执行工具；按原问题附加固定的格式纠正指令，最多干净重试一次，继续受原60秒累计模型预算约束。第二次仍无效就返回协议错误，不猜参数、不执行 SQL、不覆盖之前提交的会话状态。正常工具成功后不重试，避免重复导出；重试 token 计入总量，上下文峰值按单次请求统计。

日志只记录工具名、参数字符数、失败类别及是否重试，不记录原参数和思考正文。未来如果出现此类问题，可直接从已有日志确认原因，无需额外执行排查命令。

## 部署

把总 ZIP 原文件放到现有项目目录，执行这一行即可：

```sh
unzip -o energy-agent-20261029-v7.zip -d update-v7 && bash update-v7/部署更新.sh
```

分包和校验文件保持在 update-v7 同一目录。脚本会验证文件，备份并完整替换 app/scripts 与 main.py/chat.html/清单，然后 stop/start 现有 energy 容器。保留实际 .env、日志、导出和业务目录，不重建容器、不修改网络、不执行 DDL。部署结果自动写入 update-v7/部署结果.txt。

## 验收

在新对话连续重复三次同样问题，确认工具查询及 Excel 均成功；再在同一对话验证湘潭→株洲→中等扩展。“你好”仍应记录 fixed_guidance_local 和远程调用0次。出现 tool_arguments_invalid 时，若第一次格式纠正成功，后续只执行一次真实工具；若仍失败，应明确报告模型协议问题，不能显示为已完成。

本地使用真实 Agent/Toolkit/协议事件并替换外部模型和数据库边界验证；不代表已在内网模型验证成功率。若模型连续生成错误格式，仍会安全失败；本修复不会把无效模型输出伪装成正确查询。
